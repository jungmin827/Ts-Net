# TS-Net 디자인 시안 의뢰 프롬프트

Claude Design에 그대로 붙여넣어 사용한다. 카피가 확정되면 §7의 슬롯만 교체해 재의뢰한다.

---

## 여기서부터 복사

당신은 한국 시장용 **전환 중심 랜딩 페이지**를 설계하는 시니어 프로덕트 디자이너다.
아래 브리프를 읽고 **TS넷(TS-Net)** 홈페이지의 디자인 시안을 만들어 달라.

---

### 1. 이 사이트가 하는 일 (가장 중요)

TS넷은 **인터넷·IPTV 신규 가입 상담을 받는 인바운드 DB수집 랜딩 사이트**다.
KT / SK브로드밴드 / LG유플러스 / KT스카이라이프 4개 통신사 상품을 비교 안내하고,
방문자가 **이름과 연락처를 남기면** 상담사가 전화로 가입을 진행한다.

- **이 사이트의 유일한 성공 지표는 "이름 + 연락처 제출"이다.** 그 외 모든 요소는 이 행동을 돕기 위해 존재한다.
- 사이트에서 결제·계약이 일어나지 않는다. 회원가입도 로그인도 없다.
- 따라서 화면 어디에 있든 **3초 안에 상담 신청 수단에 닿을 수 있어야** 한다.

### 2. 방문자

- **모바일 비중이 절대적이다 (70~85%).** 네이버·구글 검색광고와 블로그를 통해 들어온다. **모바일을 1순위로 디자인하고 데스크톱을 확장으로 설계하라.**
- 이사·신축 입주·약정 만료를 앞두고 **여러 사이트를 비교 중**이다. 체류 시간이 짧고 이탈이 쉽다.
- 연령대가 넓다(20대 후반~60대). **작은 글씨, 저대비 텍스트, 미세한 터치 타깃은 실패한다.**
- 이 업계 사이트에 대한 **신뢰도가 기본적으로 낮다.** "번호 남기면 스팸 전화 오는 거 아냐?"가 기본 심리다.
  → 신뢰 장치(사업자 정보, 실제 후기, 절차 투명성, 개인정보 보호 안내)가 전환에 직접 기여한다.

### 3. 경쟁사 분석과 우리의 차별화 전략 (디자인 방향의 핵심 근거)

경쟁 레퍼런스 2곳을 분석했다. **구조는 업계 공통 패턴이라 따르되, 시각 언어는 정반대로 간다.**

**공통 구조 패턴 (검증된 것 — 유지한다)**
1. 상단 고정 헤더에 통신사 메뉴 + 대표번호를 항상 노출
2. **스크롤을 따라다니는 한 줄짜리 퀵상담 바** (관심상품·이름·연락처·동의·버튼) — 이 업계의 가장 강력한 전환 장치
3. 상담폼을 첫 화면에서 바로 노출 (스크롤 없이 폼이 보임)
4. **실시간 신청 현황 테이블** (날짜 / 통신사 / `김**` / 진행상태 / 사은품상태) — 사회적 증거
5. 차별점 카드 → 가입절차 스텝 → 후기 → 푸터 순서
6. 모바일 하단 고정바 (전화걸기 / 상담신청 2분할)

**경쟁사의 시각 언어 (의도적으로 피한다)**
- 노랑·주황 형광색 배경, 무료 3D 렌더 클립아트, 그림자 남발한 워드아트
- "차액 120% 보상", "최대 220만원" 같은 근거 없는 대형 숫자를 화면 절반에 배치
- 결과: **싸구려 떨이 판매 사이트**처럼 보이고, 신뢰도가 낮은 방문자를 더 불안하게 만든다

**TS넷의 전략적 포지션 — "통신사 전문 상담 창구"**
> 경쟁사가 **소리치는 전단지**라면, TS넷은 **차분하고 정확한 상담 창구**다.
> 금융·보험 비교 서비스에 가까운 절제된 신뢰감으로, 같은 업종에서 확실히 구별되게 한다.
> 단, 차분함이 **밋밋함이나 무기력함이 되어선 안 된다.** 전환 동선은 여전히 공격적이어야 한다.

### 4. 브랜드 컬러 — 밝은 남색 (절대 규칙)

**TS넷의 아이덴티티 컬러는 "약간 밝은 남색"이다. 모든 컨셉 시안에서 이 중심은 바뀌지 않는다.**

| 역할 | 값 | 사용처 |
|---|---|---|
| Brand (주조색) | `#2B50C8` | 로고, 주요 버튼, 강조 텍스트, 헤딩 포인트 |
| Brand Deep | `#1D379B` | 히어로 그라데이션 딥엔드, 호버, 다크 밴드 |
| Brand Tint | `#EAF0FF` | 섹션 배경 틴트, 표 헤더, 뱃지 배경 |
| Accent | `#F59E0B` | **CTA 버튼과 사은품 강조에만** — 남색과 대비되어 클릭을 유도. 남용 금지 |
| Neutral | `#FFFFFF` / `#F8FAFC` / `#64748B` / `#171717` | 배경, 보조 배경, 보조 텍스트, 본문 |

**통신사 아이덴티티 컬러** (KT `#E4002B` / SK `#EA5B0C` / LG `#E6007E` / 스카이라이프 `#00A0E9`)
→ **뱃지, 카드 상단 보더, 아이콘에만 액센트로 사용한다.**
→ 절대 배경 전면에 쓰지 마라. 통신사 페이지가 TS넷이 아닌 통신사 사이트처럼 보이면 실패다.

**남색 운용 지침**
- 면적의 60~70%는 화이트/뉴트럴, 20~30%가 남색, 5~10%가 액센트. 남색을 벽지처럼 깔지 마라.
- 남색은 **구조(헤더, 히어로, 전환 밴드, 푸터)** 에 쓰고, 콘텐츠 영역은 밝게 유지해 가독성을 확보한다.
- 다크모드는 만들지 않는다. 라이트 테마 고정.

### 5. 요구 구조 — 무한 스크롤 내러티브

**"상단 메뉴 → 스크롤하며 계속 이어지는 홍보·소개 섹션들 → 상담 받는 푸터"** 구조로 설계한다.
각 섹션은 **독립된 홍보 템플릿 카드**처럼 작동해서, 운영자가 나중에 순서를 바꾸거나 섹션을 추가·제거해도
레이아웃이 무너지지 않아야 한다. (섹션 단위 모듈 시스템으로 설계하라.)

스크롤 내러티브는 **"불안 → 이해 → 신뢰 → 행동"** 순서로 설계한다:

| # | 섹션 | 전환 역할 | 필수 요소 |
|---|---|---|---|
| 0 | **고정 헤더** | 상시 접근 | 로고 / 통신사 4메뉴 / 가입후기 / 정보공유 / 대표번호 CTA. 모바일은 햄버거 + 전화 버튼 |
| 0' | **스티키 퀵상담 바** | 상시 전환 | 스크롤 임계점 이후 상단(또는 하단)에 등장하는 한 줄 폼. 접기 가능. **가장 중요한 컴포넌트** |
| 1 | **히어로** | 후킹 | 헤드라인 / 서브카피 / CTA. **폼을 우측에 붙인 2컬럼 배치를 1안으로 검토** (스크롤 없이 폼 노출) |
| 2 | **인라인 상담폼** | 1차 전환 | 통신사 / 관심상품 / 이름 / 연락처 / 동의 2종 / 제출. 히어로에 폼이 있으면 이 섹션은 하단 폼과 통합 가능 |
| 3 | **통신사 4카드 허브** | 탐색 | KT·SK·LG·스카이라이프 카드 → 각 서브페이지 진입. 통신사 컬러 코딩 |
| 4 | **실시간 신청 현황** | 사회적 증거 | 날짜 / 통신사 / `김**` / 진행상태 / 사은품상태. 세로 롤링 애니메이션 |
| 5 | **차별점 4카드** | 이해 | 아이콘 + 제목 + 2~3줄. 커스텀 아이콘 세트 필요 |
| 6 | **가입절차 5스텝** | 불안 해소 | 상담 → 접수 → 일정조율 → 설치 → 사은품. 데스크톱 가로 연결, 모바일은 세로 또는 3+2 그리드 |
| 7 | **요금 비교 프리뷰** | 비교 욕구 충족 | 통신사별 대표 상품 표/카드 미리보기 + "전체 보기" → 서브페이지 |
| 8 | **후기** | 신뢰 | 썸네일 / 제목 / 별점 / 발췌 / 날짜. 슬라이더 또는 그리드 + "후기 보러가기" |
| 9 | **신뢰 섹션** | 신뢰 | 사업자등록·통신판매신고 등 증빙, 개인정보 보호 안내 (암호화 저장·자동 파기) |
| 10 | **FAQ 아코디언** | 마지막 장벽 제거 | 5~7문항. "전화 많이 오나요" "설치 얼마나 걸리나요" 같은 실제 불안 |
| 11 | **상담 푸터 (전환 푸터)** | 최종 전환 | **아래 별도 설명** |
| 12 | **모바일 하단 고정바** | 상시 전환 | 전화걸기 / 상담신청 2분할 |

**§11 상담 푸터는 이 시안의 하이라이트다.** 단순 저작권 표기가 아니라 **마지막 전환 구역**으로 설계한다:

```
┌─────────────────────────────────────────────┐
│  [남색 풀블리드 밴드]                          │
│  큰 헤드라인 + 짧은 설득 문장                   │
│  ┌───────────────┐  ┌──────────────────┐    │
│  │ 상담 신청 폼    │  │ 전화 상담 블록     │    │
│  │ (핵심 필드만)   │  │ 대표번호 크게      │    │
│  └───────────────┘  │ 운영시간          │    │
│                     └──────────────────┘    │
├─────────────────────────────────────────────┤
│  [뉴트럴 영역] 사업자 정보 6종 · 약관 링크       │
└─────────────────────────────────────────────┘
```
사업자 정보는 **법적 필수 표기**라 반드시 들어가되, 시각적으로는 조용한 하단 영역에 배치한다.

### 6. 반드시 지켜야 하는 제약 (법적 요건 — 협상 불가)

1. **개인정보 수집·이용 동의(필수)와 마케팅 정보 수신 동의(선택)는 반드시 별개 체크박스로 분리한다.**
   하나로 묶으면 위법이다. 두 체크박스의 위계 차이(필수 vs 선택)가 시각적으로 드러나야 한다.
2. **실시간 신청 현황은 실제 접수 데이터만 마스킹해 노출한다.** 가짜 데이터를 채우지 않는다.
   → **데이터가 5건 미만이면 섹션이 통째로 사라지는 상태를 반드시 함께 디자인하라.**
   (레이아웃이 섹션 하나 없어도 자연스러워야 한다.)
3. **근거 없는 수치 광고 문구를 디자인에 하드코딩하지 마라.** "최대 N만원", "보상률 N%" 같은 표현은
   운영자가 근거에 맞춰 수정할 **설정값 슬롯**으로 비워두고, 자리표시자로 표기한다.
4. 푸터에 **상호 / 대표자 / 사업자등록번호 / 부가통신사업 신고번호 / 통신판매업 신고번호 / 주소** 6종 필수.
5. **레퍼런스 사이트의 문구·이미지·CSS를 복제하지 마라.** 구조 패턴은 업계 공통이라 무방하지만
   카피와 그래픽 에셋은 전부 새로 만든다.
6. 폼에는 **봇 방지(Cloudflare Turnstile) 위젯 자리**와 **보이지 않는 honeypot 필드**가 들어간다.
   Turnstile 위젯은 65px 내외 높이를 차지한다 — 레이아웃에 미리 반영하라.

### 7. 카피 슬롯

**실제 홍보 카피와 템플릿은 운영자가 별도 제작해 나중에 주입한다.**
따라서 모든 텍스트를 `{{ }}` 슬롯으로 표기하고, **글자 수가 늘거나 줄어도 레이아웃이 버티도록** 설계하라.
시안에는 실제 분량감을 보여주는 한국어 더미 카피를 넣되, 과장 광고 표현은 쓰지 않는다.

- 헤드라인: 한글 15~30자 (2줄 이내)
- 서브카피: 한글 25~50자
- 카드 제목: 8~14자 / 카드 본문: 줄당 15~22자 × 2~3줄
- CTA 버튼: 4~8자

### 8. 디자인 시스템 요구사항

**타이포그래피**
- 본문 폰트: **Pretendard** (한국어 UI 표준) — 대체로 Noto Sans KR
- 한국어는 `word-break: keep-all`로 조사 단위 줄바꿈을 막는다
- 모바일 본문 최소 15px, 터치 타깃 최소 48×48px
- **금액·숫자는 별도 위계로 강조** (더 굵게, 더 크게, 브랜드 컬러) — 이 업종에서 숫자는 핵심 정보다

**컴포넌트 (상태별로 전부 그려라)**
- 버튼: Primary(남색) / Accent(주황) / Outline / Ghost × default·hover·pressed·disabled·loading
- 입력 필드: default·focus·error·filled / 셀렉트 / 체크박스(필수·선택 구분) / 전화번호 입력
- 폼 상태: **입력 전 / 검증 실패 / 제출 중 / 성공 / 중복 접수("오늘 이미 접수되었습니다")**
  → 이 5가지 상태를 전부 디자인하라. 실패 상태 디자인이 없는 폼은 미완성이다.
- 카드: 통신사 카드 / 요금제 카드 / 후기 카드 / 차별점 카드
- 표: 요금제 표(모바일에서 가로 스크롤), 실시간 현황 표
- 뱃지: 통신사 4종 / 상태(접수완료·진행중·설치완료) / 사은품 상태
- 모달: 약관 / 제휴카드 안내
- 아코디언, 페이지네이션, 토스트

**모션 (절제해서)**
- 스크롤 진입 시 fade-up (거리 짧게, 12~16px, 200~300ms)
- 실시간 현황 세로 무한 롤링
- 스티키 퀵바 등장/퇴장 트랜지션
- **패럴랙스, 과한 이징, 자동재생 영상은 쓰지 마라.** 모바일 성능(Lighthouse 80점 이상)이 요구사항이다.

**접근성**
- 본문 대비 4.5:1 이상. 남색 배경 위 흰 텍스트는 충분하지만 **주황 위 흰 텍스트는 대비를 검증하라.**
- 포커스 링을 지우지 말 것. 폼 오류는 색만이 아니라 아이콘+문구로도 전달.

### 9. 요청하는 결과물

**(A) 컨셉 3종 제안 — 히어로 + 대표 섹션 2개씩**

같은 정보 구조 위에서 **성격이 뚜렷이 다른 3가지 시각 방향**을 제시하라. 셋 다 밝은 남색이 중심이다.
아래는 출발점 제안이며, 더 나은 방향이 있으면 대체해도 좋다. 각 컨셉에 **이름과 한 줄 논지**를 붙여라.

1. **"신뢰형" — 금융 비교 서비스 톤**
   넓은 여백, 화이트 베이스에 남색 구조, 얇은 보더와 낮은 그림자, 정갈한 카드 그리드.
   장점: 최고 수준의 신뢰감, 넓은 연령대 수용. 리스크: 자칫 심심하고 전환 압력이 약해질 수 있음.

2. **"비교 대시보드형" — 데이터 우선**
   히어로 자체가 비교 도구. 통신사·속도·결합 조건을 칩(chip)으로 고르면 예상 요금이 즉시 갱신.
   숫자와 표가 전면에. 남색 틴트를 데이터 표면 색으로 활용.
   장점: 비교 목적 방문자에게 압도적. 리스크: 정보 밀도가 높아 모바일 설계 난이도 상승.

3. **"스토리 스크롤형" — 에디토리얼**
   풀블리드 섹션이 교차하며 한 챕터씩 전개(문제 제기 → 해결 → 증거 → 행동).
   큰 타이포그래피, 남색 밴드와 화이트 섹션의 리듬, 스크롤 연동 등장.
   장점: 요청한 "무한 스크롤 홍보 템플릿" 구조에 가장 부합, 브랜드 인상이 강함. 리스크: 스크롤 깊이가 길어짐.

**각 컨셉마다 반드시 밝혀라:** 어떤 방문자에게 유리한지 / 전환율 관점의 장단점 / 어떤 카피 스타일과 맞는지.

**(B) 선정안 풀 시안**
3안 중 **당신이 추천하는 1안을 명시하고 그 근거를 설명한 뒤**, 그 방향으로 전체를 완성하라.

- **모바일 390px 메인 전체 (최우선)** — §5의 모든 섹션, 스크롤 전체 흐름
- **데스크톱 1440px 메인 전체**
- **통신사 서브페이지** (KT 기준, 모바일·데스크톱) — 서브 히어로 / 추천 상품 카드 / 요금제 표 / 제휴카드 안내 / 하단 상담폼
- **후기 목록 페이지** (카드 그리드 + 페이지네이션)
- **주요 상태 화면**: 폼 성공 / 폼 오류 / 실시간 현황 5건 미만이라 섹션이 빠진 메인 / 요금제 미등록 서브페이지
- **디자인 토큰 시트**: 컬러·타이포 스케일·스페이싱·라운드·섀도우
- **컴포넌트 시트**: §8의 컴포넌트 전 상태

**(C) 구현 인계 노트**
각 섹션에 대해 — 반응형 분기점에서 무엇이 어떻게 바뀌는지, 어떤 요소가 데이터 기반이라 비거나 늘어날 수 있는지,
어떤 값이 운영자 설정값(카피·금액·이미지)인지 짧게 적어라.

### 10. 기술 컨텍스트 (시안을 구현 가능하게 만들기 위해)

- **Next.js 15 App Router + TypeScript + Tailwind CSS v4**로 구현된다.
  → 색·간격·라운드는 **Tailwind 토큰으로 표현 가능한 값**으로 설계하라(임의 픽셀 남발 금지).
- 이미지는 운영자가 교체 가능한 슬롯이어야 한다. **폰트 이미지나 텍스트가 박힌 이미지를 쓰지 마라** (수정 불가능해진다).
- 아이콘은 **일관된 커스텀 세트 또는 단일 라인 아이콘 패밀리**로. 무료 3D 클립아트를 섞지 마라.
- 현재 저장소에 스캐폴딩 수준의 러프한 구현이 있지만 **그것에 맞출 필요는 전혀 없다.**
  컬러 토큰 체계만 유지하고, 레이아웃·비주얼은 처음부터 제대로 설계하라.
