작성일: 2026-09-23. `docs/DESIGN_BRIEF_PROMPT.md`(V1)의 개정판이다.

**V1과의 차이**: V1은 시각 컨셉 3종을 열어두고 디자이너에게 방향을 고르게 하는 브리프였다.

**TS넷 밝은 남색 아이덴티티로 디테일을 완성**하게 한다. 컨셉 제안 단계는 삭제했다.

## 여기서부터 복사

당신은 한국 시장용 **전환 중심 랜딩 페이지**를 설계하는 시니어 프로덕트 디자이너다.
**TS넷(TS-Net)** 홈페이지의 1차 시안을 만들어 달라.

이 브리프는 **레이아웃 골격이 이미 확정된 상태**다. §1은 재해석 대상이 아니라 준수 대상이다.
당신이 결정할 것은 그 골격 안의 **비례·타이포·색 운용·상태 설계·모션 디테일**이다.

---

### 1. 확정 골격 (협상 불가 — 여기부터 읽어라)

동종업계 상위 사이트의 레이아웃 골격을 분석해 아래 3가지를 채택하기로 확정했다.
**구조·배치·인터랙션 패턴만** 가져오고, 문구·이미지·CSS·색은 전부 새로 만든다.
셋 다 반드시 시안에 포함되어야 하며, 순서와 구성을 바꾸지 마라.

#### 1-A. 2단 헤더 (사이트 전 페이지 공통)

헤더는 **역할이 다른 두 줄**로 나뉜다. 한 줄로 합치지 마라.

**1단 — 브랜드 존** (§1-B에서 상세히 정의)
- 높이 데스크톱 84~96px. 배경은 화이트 또는 `--brand-soft`.
- 중앙(또는 좌측 정렬 중 택1, 근거를 밝혀라)에 로고. 로고 바로 위에 **아주 작은 태그라인 한 줄**.
- **우측 끝에 대표번호 버튼** — 아웃라인 알약형(fill 아님). 남색 보더 + 남색 텍스트 + 수화기 아이콘.
  1단에서는 채워진 버튼을 쓰지 않는다. 채워진 버튼은 2단 CTA의 자리다.
- 좌우 여백이 넓어야 한다. 로고가 다른 요소에 끼어 있는 인상이면 실패다.

**2단 — 내비 바**
- 높이 56~64px. 1단과 1px 보더 또는 미세한 배경 차이로 분리.
- 메뉴 항목이 **가로 균등 배치**된다 (좌측 몰림·중앙 뭉침 금지).
  항목: `KT` / `SK브로드밴드` / `LG유플러스` / `KT스카이라이프` / `가입후기` / `정보공유` (6개).
- **맨 우측에 채워진 컬러 CTA 버튼**(`{{cta_nav}}`, 4~8자). 내비 항목들과 시각적으로 분리되어
  "이건 메뉴가 아니라 행동 버튼"임이 즉시 읽혀야 한다. 색은 `--accent`를 쓴다.
- 활성 페이지 표시: 하단 2px `--brand` 언더라인 + 텍스트 굵기 상승.
- **스크롤 동작**: 스크롤이 임계점(약 120px)을 넘으면 **1단은 접히고 2단만 상단에 고정**된다.
  전환 180~220ms. 접힌 상태에서는 2단 좌측에 축소 로고가 슬라이드 인한다.
  → 펼친 상태 / 접힌 상태 **둘 다 그려라.**

**모바일(390px) 대응** — 2단을 그대로 축소하지 마라.
- 1단: 좌측 로고 / 우측 전화 아이콘 버튼 + 햄버거. 높이 56~60px.
- 2단: **가로 스크롤 칩 바**로 변환(통신사 4개 + 게시판 2개)하거나, 햄버거 드로어로 흡수 — 택1하고 근거를 밝혀라.
  가로 스크롤을 택하면 **우측이 잘리는 시각적 힌트**(페이드 마스크)를 반드시 넣어라.
- 모바일에서 채워진 CTA는 헤더가 아니라 **하단 고정바**(§5 №12)가 담당한다. 중복 배치 금지.

#### 1-B. 와이드 캔버스 위 브랜드 로고 존

헤더 1단은 단순한 "로고 놓는 자리"가 아니라 **브랜드가 숨 쉬는 독립 영역**으로 설계한다.

| 요소 | 규격 | 비고 |
|---|---|---|
| 태그라인 | 11~12px, 자간 +0.04em, `--muted` | `{{tagline}}` 10~20자. 로고 **위**에 한 줄 |
| 로고 | 높이 36~44px | 심볼 + 로고타입. **텍스트가 박힌 이미지 금지** — 도형+텍스트 조합으로 |
| 로고 상하 여백 | 각 20~28px | 이 여백을 줄이지 마라. 골격의 핵심이다 |
| 좌우 안전 영역 | 로고 블록 기준 좌우 각 최소 160px(1440 기준) | 대표번호 버튼은 이 영역 밖 우측 끝 |
| 컨테이너 | max-width 1200~1280px, 배경은 풀폭 | 캔버스는 넓고 콘텐츠는 가운데 |

- 로고 컨셉도 함께 제안하라. `TS`를 활용한 기하학적 심볼 + 한글/영문 로고타입.
  남색 단색으로 작동해야 하고, 16px 파비콘 크기에서도 형태가 유지되어야 한다.
- 로고 존 배경을 남색으로 채우지 마라. 남색은 히어로·밴드·푸터의 몫이다.

#### 1-C. 풀폭 애니메이션 홍보 카피 밴드 (이 시안의 하이라이트)

히어로 **바로 아래**에 들어가는 풀폭 컬러 밴드. 단어가 순차 교체되며 한 문장이 완성된다.

**구조**
- 풀블리드 폭, **라운드 없이 사각**. 좌우에 내부 여백만 둔다.
- 높이: 데스크톱 150~180px 고정 / 태블릿 128px / 모바일 96~120px 고정.
  **내용에 따라 높이가 변하면 안 된다** — 가장 긴 슬롯 기준으로 고정해 레이아웃 시프트를 없애라.
- 배경: `--brand-deep` 또는 `--brand`. 그 위 텍스트는 화이트.
  값 슬롯 한 개에만 `--accent`를 허용한다(밴드 전체를 주황으로 만들지 마라).

**단어 슬롯 구조 (4슬롯)** — 문장은 슬롯 4개가 순서대로 나타나 완성된다.

| # | 슬롯 키 | 역할 | 글자 수 | 서식 |
|---|---|---|---|---|
| 1 | `{{band_lead}}` | 도입어 | 2~4자 | 화이트, 900 |
| 2 | `{{band_brand}}` | 브랜드/주체 | 3~8자 | 화이트, 900 |
| 3 | `{{band_qualifier}}` | 한정어 | 2~4자 | 화이트, 900 |
| 4 | `{{band_value}}` | 값·혜택 | 4~12자 | `--accent`, 900 |

- 각 단어는 **초대형 타이포**: 데스크톱 `clamp(64px, 7vw, 120px)` / 모바일 34~48px.
  화면 폭의 30~50%를 차지할 만큼 크게. 이것이 이 밴드의 존재 이유다.
- 단어 하나가 화면에 머무는 시간 **2.2~2.8초**, 교체 전환 **0.35~0.45초**.
  4슬롯 1회 순환 약 10~13초. 순환은 무한 반복하되 마지막 슬롯은 +0.8초 더 머문다.
- 교체 모션: **위→아래 슬라이드(12~20px) + 페이드**, 또는 마스크 와이프. 이징 `cubic-bezier(0.22,1,0.36,1)`.
  튀는 바운스·회전·3D 플립은 쓰지 마라.
- 단어의 **수평 정렬 기준점을 명시하라** (중앙 정렬 권장). 글자 수가 달라도 중심이 흔들리지 않아야 한다.
- 슬롯이 비면(운영자가 `{{band_value}}`를 안 채우면) **3슬롯으로 자연 축소**되어야 한다.
  → 4슬롯 상태와 3슬롯 상태를 둘 다 그려라.

**모바일 대응 (필수 명세)**
- 데스크톱과 동일한 4슬롯 순차 교체를 유지하되 타이포 스케일만 낮춘다. 슬롯을 합치거나 줄이지 마라.
- 한 단어가 모바일 폭(390px)을 넘으면 **자동 축소(clamp)**로 처리한다. 줄바꿈시키지 마라 — 높이가 흔들린다.
- 모바일에서는 단어 체류 시간을 **2.0~2.4초로 약간 단축**한다(스크롤 속도가 빠르므로).
- 밴드가 뷰포트 밖에 있을 때는 애니메이션을 정지시킨다(배터리·성능).

**접근성·법적 처리 (필수)**
- `prefers-reduced-motion` 시 애니메이션을 끄고 **네 단어를 한 줄에 동시 표시한 정적 버전**을 보여준다.
  → **이 정적 대체 시안도 반드시 그려라.**
- 스크린리더에는 완성된 문장 전체를 한 번에 읽히고, 개별 단어 노드는 숨긴다.
- `{{band_value}}`가 금액·수치일 경우 **밴드 하단에 조건 각주 한 줄**(11~12px, 화이트 70% 투명도)이
  들어갈 자리를 반드시 확보하라. 예: `{{value_condition}}` — "조건·상한·적용 대상" 표기용.
  수치만 크게 띄우고 조건이 없는 화면은 광고법 위반 소지가 있어 채택 불가다.

### 2. 이 사이트가 하는 일

TS넷은 **인터넷·IPTV 신규 가입 상담을 받는 인바운드 DB수집 랜딩 사이트**다.
KT / SK브로드밴드 / LG유플러스 / KT스카이라이프 4사 상품을 비교 안내하고,
방문자가 **이름과 연락처를 남기면** 상담사가 전화로 가입을 진행한다.

- **유일한 성공 지표는 "이름 + 연락처 제출"이다.** 다른 모든 요소는 이 행동을 돕기 위해 존재한다.
- 사이트에서 결제·계약·회원가입·로그인이 일어나지 않는다.
- 화면 어디에 있든 **3초 안에 상담 신청 수단에 닿아야** 한다.

**방문자**
- **모바일 70~85%.** 검색광고·블로그 유입. 모바일을 1순위로 설계하고 데스크톱을 확장으로 본다.
- 이사·입주·약정 만료를 앞두고 **여러 사이트를 비교 중**. 체류가 짧고 이탈이 쉽다.
- 연령대가 넓다(20대 후반~60대). 작은 글씨·저대비 텍스트·미세한 터치 타깃은 실패한다.
- **업계 신뢰도가 기본적으로 낮다.** "번호 남기면 스팸 오는 거 아냐?"가 기본 심리다.
  → 사업자 정보·실제 후기·절차 투명성·개인정보 보호 안내가 전환에 직접 기여한다.

**포지션 — "통신사 전문 상담 창구"**
> 경쟁사가 **소리치는 전단지**라면 TS넷은 **차분하고 정확한 상담 창구**다.
> 금융·보험 비교 서비스에 가까운 절제된 신뢰감으로 같은 업종에서 구별되게 한다.
> 단, 차분함이 **밋밋함이 되어선 안 된다.** 전환 동선은 여전히 공격적이어야 한다.
> §1-C의 대형 애니메이션 밴드가 바로 그 "공격적인 한 방"이다. 절제와 임팩트의 균형을 그 대비로 만든다.

**경쟁사에서 의도적으로 피하는 것**: 형광 노랑·주황 배경, 무료 3D 렌더 클립아트,
그림자 남발한 워드아트, 근거 없는 대형 숫자를 화면 절반에 배치하는 방식.

### 3. 컬러 — 밝은 남색 (확정값, 변경 불가)

레퍼런스는 주황 기조지만 **TS넷은 밝은 남색을 따라간다.** 주황 기조로 끌려가면 실패다.

| 토큰 | 값 | 사용처 |
|---|---|---|
| `--brand` | `#2B50C8` | 주조색. 로고, 주요 버튼, 강조 텍스트, 활성 표시 |
| `--brand-dark` | `#1D379B` | 호버, 그라데이션 중간 |
| `--brand-deep` | `#152A75` | 히어로·애니메이션 밴드·푸터 딥엔드 |
| `--brand-light` | `#EAF0FF` | 섹션 틴트, 표 헤더, 뱃지 배경 |
| `--brand-soft` | `#F5F8FF` | 가장 옅은 배경 틴트 |
| `--accent` | `#F59E0B` | **CTA 버튼과 밴드 값 슬롯에만.** 남용 금지 |
| Neutral | `#FFFFFF` / `#F7F9FC` / `#E8EDF5`(line) / `#64748B`(muted) / `#171717` | 배경·보더·본문 |

**통신사 컬러** KT `#E4002B` / SK `#EA5B0C` / LG `#E6007E` / 스카이라이프 `#00A0E9`
→ **뱃지·카드 상단 보더·아이콘에만** 액센트로. 배경 전면에 쓰면 TS넷이 아니라 통신사 사이트처럼 보인다.

**운용 지침**
- 면적 비율 60~70% 화이트·뉴트럴 / 20~30% 남색 / 5~10% 액센트. 남색을 벽지처럼 깔지 마라.
- 남색은 **구조**(헤더 활성표시, 히어로, 애니메이션 밴드, 전환 푸터)에, 콘텐츠 영역은 밝게.
- 그림자는 검정이 아니라 남색(`rgb(21 42 117 / α)`)을 섞는다. 브랜드와 같은 공기 안에 있게.
- **다크모드는 만들지 않는다.** 라이트 테마 고정.

### 4. 페이지 구조 (위→아래)

각 섹션은 **독립 모듈**이다. 운영자가 순서를 바꾸거나 섹션을 빼도 레이아웃이 무너지면 안 된다.
스크롤 내러티브는 **"후킹 → 이해 → 신뢰 → 행동"**.

| # | 섹션 | 역할 | 필수 요소 |
|---|---|---|---|
| 0 | **2단 헤더** (§1-A·1-B) | 상시 접근 | 확정 골격 |

### 5. 법적 제약 (협상 불가)

1. **개인정보 수집·이용 동의(필수)와 마케팅 정보 수신 동의(선택)는 반드시 별개 체크박스.**
   묶으면 위법이다. 필수/선택의 위계 차이가 **시각적으로** 드러나야 한다.
2. **실시간 신청현황은 실제 접수 데이터만 마스킹해 노출한다.** 가짜 데이터를 채우지 않는다.
   → **5건 미만이라 섹션이 통째로 사라진 메인 화면을 반드시 함께 디자인하라.**
   섹션 하나가 빠져도 위아래 리듬이 자연스러워야 한다.
3. **근거 없는 수치를 디자인에 하드코딩하지 마라.** "최대 N만원", "보상률 N%"는 운영자가 근거에 맞춰
   채울 **설정값 슬롯**으로 비워둔다. 수치를 쓰는 화면에는 **조건·상한·적용 대상 각주**를 같은 화면에 둔다.
4. 푸터에 **상호 / 대표자 / 사업자등록번호 / 부가통신사업 신고번호 / 통신판매업 신고번호 / 주소**
   6종 필수. 법적 필수 표기이므로 반드시 넣되, 시각적으로는 조용한 하단 영역에 배치한다.
5. **레퍼런스 사이트의 문구·이미지·CSS를 복제하지 마라.** §1의 골격은 업계 공통 구조라 무방하지만,
   카피와 그래픽 에셋은 전부 새로 만든다.
6. 폼에 **봇 방지 위젯 자리(약 65px 높이)**와 **보이지 않는 honeypot 필드**가 들어간다. 레이아웃에 미리 반영하라.

### 6. 카피 슬롯 (운영자가 나중에 주입)

**실제 홍보 카피는 운영자가 별도 제작해 주입한다.** 모든 텍스트를 `{{ }}` 슬롯으로 표기하고,
**글자 수가 늘거나 줄어도 레이아웃이 버티도록** 설계하라.
시안에는 분량감을 보여주는 한국어 더미 카피를 넣되, 과장 표현은 쓰지 않는다.

| 영역 | 슬롯 | 분량 |
|---|---|---|
| 헤더 태그라인 | `{{tagline}}` | 10~20자 |
| 내비 CTA | `{{cta_nav}}` | 4~8자 |
| 히어로 헤드라인 | `{{hero_headline}}` | 15~30자 / 2줄 이내 |
| 히어로 서브카피 | `{{hero_sub}}` | 25~50자 |
| 히어로 CTA | `{{hero_cta}}` | 4~8자 |
| 신뢰 칩 ×3 | `{{trust_chip_1~3}}` | 각 8~14자 |
| 애니메이션 밴드 | `{{band_lead}}` / `{{band_brand}}` / `{{band_qualifier}}` / `{{band_value}}` | 2~4 / 3~8 / 2~4 / 4~12자 |
| 밴드 조건 각주 | `{{value_condition}}` | 20~40자 |
| 차별점 카드 ×4 | 제목 / 본문 | 제목 8~14자, 본문 줄당 15~22자 × 3줄 |
| 가입절차 ×5 | 제목 / 설명 | 제목 4~8자, 설명 8~14자 |
| 전환 푸터 밴드 | 헤드라인 / 서브 | 12~20자 / 20~30자 |

**CTA 문구 원칙**: 버튼은 "무엇을 해야 하는지"(행동형)보다 **"무엇을 얻는지"(획득형)**가 전환에 유리하다.
행동형·획득형 두 변형을 각각 제시하고 추천안을 밝혀라.

### 7. 디자인 시스템

**타이포그래피**
- 본문 폰트 **Pretendard** (대체 Noto Sans KR). 헤드라인 900 / 본문 400 / 숫자 700.
- 한국어는 `word-break: keep-all` — 조사 단위 줄바꿈 방지.
- 모바일 본문 최소 15px, 터치 타깃 최소 48×48px.
- **금액·숫자는 별도 위계로 강조**(더 굵게·더 크게·브랜드 컬러). 이 업종에서 숫자는 핵심 정보다.

**컴포넌트 — 상태별로 전부 그려라**
- 버튼: Primary(남색) / Accent(주황) / Outline / Ghost × default·hover·pressed·disabled·loading
- 입력: default·focus·error·filled / 셀렉트 / 전화번호 입력 / **체크박스(필수·선택 시각 구분)**
- 폼 상태 5종: **입력 전 / 검증 실패 / 제출 중 / 성공 / 중복 접수("오늘 이미 접수되었습니다")**
  → 실패 상태 디자인이 없는 폼은 미완성이다.
- 카드: 통신사 / 요금제 / 후기 / 차별점
- 표: 요금제 표(모바일 가로 스크롤), 실시간 현황 표
- 뱃지: 통신사 4종 / 진행상태(접수완료·진행중·설치완료) / 사은품 상태
- 모달(약관·제휴카드), 아코디언, 페이지네이션, 토스트

**모션 (절제)**
- 스크롤 진입 fade-up: 이동 12~16px, 200~300ms
- 실시간 현황 세로 무한 롤링
- 헤더 1단 접힘 전환 180~220ms
- §1-C 애니메이션 밴드 — 유일하게 큰 모션이 허용된 구역
- **패럴랙스, 과한 이징, 자동재생 영상, 스크롤 하이재킹 금지.** Lighthouse 모바일 80점 이상이 요구사항이다.

**접근성**
- 본문 대비 4.5:1 이상. 남색 배경 위 화이트는 충분하지만 **주황 위 화이트는 대비를 검증하라**(어두운 텍스트가 안전할 수 있다).
- 포커스 링을 지우지 마라. 폼 오류는 색만이 아니라 아이콘+문구로도 전달.
- 모든 애니메이션에 `prefers-reduced-motion` 대체안을 둔다.

### 8. 요청하는 결과물

컨셉 제안 단계는 없다. §1 골격 위에서 **바로 완성안**을 만든다.

**(A) 전체 시안**
- **모바일 390px 메인 전체** (최우선) — §4의 모든 섹션, 스크롤 전체 흐름
- **데스크톱 1440px 메인 전체** — §4의 모든 섹션
- **헤더 상세**: 데스크톱 펼침 / 데스크톱 접힘(스티키) / 모바일 닫힘 / 모바일 드로어 열림 — 4종
- **애니메이션 밴드 상세**: 4슬롯 각 프레임(단어 1→2→3→4) / 전환 중간 프레임 1장 /
  3슬롯 축소 상태 / `prefers-reduced-motion` 정적 버전 / 모바일 버전 — 타임라인 수치를 함께 표기
- **통신사 서브페이지**(KT 기준, 데스크톱·모바일) — 서브 히어로 / 추천 상품 카드 / 요금제 표 / 제휴카드 안내 / 하단 상담폼
- **후기 목록 페이지** — 카드 그리드 + 페이지네이션

**(B) 상태 화면 (필수)**
- 폼 **성공** / 폼 **검증 오류** / 폼 **제출 중** / **중복 접수**
- **실시간 현황이 5건 미만이라 섹션이 빠진 메인** (데스크톱·모바일 둘 다)
- **요금제 미등록 서브페이지** (표 대신 상담 유도로 대체된 상태)
- 밴드 값 슬롯이 비어 **3슬롯으로 축소된 상태**

**(C) 디자인 토큰 시트**
컬러(§3 전 토큰 + 통신사 4색) / 타이포 스케일 / 스페이싱 / 라운드 / 섀도우 / 이징·듀레이션.
**Tailwind CSS v4 토큰으로 표현 가능한 값**으로 정의하라(임의 픽셀 남발 금지).

**(D) 컴포넌트 시트**
§7의 컴포넌트 전 상태.

**(E) 구현 인계 노트**
섹션별로 — 반응형 분기점에서 무엇이 어떻게 바뀌는지 / 어떤 요소가 데이터 기반이라 비거나 늘어날 수 있는지 /
어떤 값이 운영자 설정값(카피·금액·이미지)인지. 애니메이션 밴드는 **슬롯·타이밍·이징을 수치로** 적어라.

### 9. 기술 컨텍스트

- **Next.js 15 App Router + TypeScript + Tailwind CSS v4**로 구현된다. 라이트 테마 고정, SSG 중심.
- 색·간격·라운드는 CSS 변수 토큰 한 곳에서 관리된다. 시안의 토큰명을 §3 표기와 일치시켜라.
- 이미지는 운영자가 교체 가능한 슬롯이어야 한다. **텍스트가 박힌 이미지를 쓰지 마라**(수정 불가능해진다).
- 아이콘은 **일관된 단일 라인 아이콘 패밀리**. 무료 3D 클립아트를 섞지 마라.
- 저장소에 스캐폴딩 수준의 구현이 있지만 **거기에 맞출 필요는 없다.** 토큰 체계만 유지하고 레이아웃은 새로 설계하라.

### 10. 하지 말아야 할 것

- 2단 헤더를 1단으로 합치기 / 브랜드 로고 존의 여백 축소 / 애니메이션 밴드 생략·축소

- 형광색 배경, 무료 3D 렌더 클립아트, 그라데이션 워드아트
- 화면을 덮는 팝업, 자동 재생 영상, 스크롤 하이재킹
- 근거 없는 대형 숫자 강조, "무조건 최저가"·"100% 보장" 류 단정 표현
- 필수/선택 동의를 하나로 묶은 체크박스
- 다크모드, 캐러셀 자동재생 5초 미만, 12px 미만 본문
- 레퍼런스 사이트의 카피·이미지·CSS 픽셀 복제

---

**마지막으로:** 이 사이트는 예쁜 것보다 **번호를 남기게 만드는 것**이 목적이다.
모든 결정에 대해 "이게 전환에 어떻게 기여하는가"를 스스로 물어라.
시안 제출 시 **당신이 내린 핵심 결정 3~5개와 그 근거**, 그리고 §1 확정 골격을
어떻게 TS넷 남색 아이덴티티로 번역했는지 짧게 적어 달라.
